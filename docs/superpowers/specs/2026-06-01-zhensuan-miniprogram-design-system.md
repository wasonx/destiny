# 甄好算小程序设计系统改造规格

日期：2026-06-01

## 1. 目标

本次选择 C 方案：为原生微信小程序建立一套完整设计系统，让小程序视觉尽量贴近 Web 端的甄好算风格，同时保持原生小程序代码路线。

本次改造目标是统一小程序的视觉语言、组件样式和页面结构，而不是重写业务逻辑。

## 2. 设计基准

Web 端当前视觉语言已经形成以下特征：

1. 背景以纸白和浅灰为主。
2. 主文字使用墨蓝色。
3. 辅助色使用沉静青绿、智慧金和朱红。
4. 页面气质偏安静、克制、可阅读。
5. 卡片边框轻，圆角克制。
6. 标题有书卷感，正文保持清晰易读。
7. 重要动作按钮使用墨蓝或青绿。
8. 报告页强调段落、摘要、行动建议、免责声明和溯源。

小程序端需要继承上述风格，但不照搬 React / Tailwind 代码。

## 3. 改造范围

本次改造覆盖 `miniprogram/` 下的原生小程序界面：

1. 全局样式 `app.wxss`。
2. 首页 `pages/home`。
3. 登录页 `pages/login`。
4. 四个报告入口页：`life`、`relationship`、`question`、`space`。
5. 报告页 `pages/report`。
6. 商城页 `pages/store`。
7. 收货地址页 `pages/address`。
8. 订单页 `pages/orders`。
9. 罗盘页 `pages/compass`。
10. 合规页 `pages/legal`。

本次不改：

1. 后端 API。
2. 登录、订单、报告、商城、权益等业务逻辑。
3. 小程序 AppID。
4. 微信真实登录链路。
5. 手机号模拟登录链路。
6. 小程序上传记录。

## 4. 设计 Token

小程序全局样式需要沉淀以下 token。微信小程序 WXSS 不支持 CSS 变量的兼容性不稳定，因此 token 以注释和统一 class 规则落在 `app.wxss` 中。

### 4.1 色彩

1. 纸白背景：`#FDFCF8`。
2. 页面浅底：`#fbf9fb`。
3. 报告浅底：`#F9FAFB`。
4. 墨蓝主色：`#1A2F4B`。
5. 沉静青绿：`#4A7C77`。
6. 智慧金：`#B89150`。
7. 朱红提示：`#C84B31`。
8. 轻边框灰：`#E5E7EB`。
9. 次级文字灰：`#6B7280`。
10. 弱提示灰：`#9CA3AF`。

### 4.2 字体和字号

小程序端无法稳定使用 Web 字体，因此采用系统中文字体，但通过字号、字重和行高模拟 Web 端气质。

1. 页面主标题：40-44rpx，字重 700。
2. 页面副标题：26-28rpx，行高 1.7。
3. 卡片标题：32-36rpx，字重 700。
4. 正文：28-30rpx，行高 1.75。
5. 辅助说明：22-24rpx，行高 1.6。
6. 小标签：20-23rpx，字距轻微拉开。

### 4.3 间距和圆角

1. 页面左右边距：32rpx。
2. 页面顶部视觉区：32-40rpx。
3. 卡片内边距：28-32rpx。
4. 卡片间距：20-24rpx。
5. 主要圆角：16rpx。
6. 小控件圆角：12rpx。
7. 胶囊标签圆角：999rpx。

圆角需要克制，保持 Web 端 8px 左右的观感，不做过度圆润。

## 5. 全局组件类

`app.wxss` 需要建立以下可复用类，页面尽量复用，减少每页重复样式。

### 5.1 页面结构

1. `.page`：统一页面内边距、背景、最小高度。
2. `.hero`：页面顶部视觉区。
3. `.brand`：金色小标识。
4. `.title`：页面标题。
5. `.subtitle`：页面说明。
6. `.section`：基础内容卡片。
7. `.section-title`：卡片标题。

### 5.2 卡片

1. `.zs-card`：普通卡片。
2. `.zs-card-accent`：左侧色条卡片，对应 Web 首页模块卡。
3. `.zs-card-gold`：金色弱强调卡片，用于升级、权益、提示。
4. `.zs-card-teal`：青绿色弱强调卡片，用于成功、登录、权益状态。

### 5.3 表单

1. `.field`。
2. `.label`。
3. `.input`。
4. `.textarea`。
5. `.chips`。
6. `.chip`。
7. `.chip.active`。
8. `.form-help`。

输入框要从“普通小程序输入框”变成接近 Web 端的纸面输入体验：浅底、细边框、明确 focus 风格。

### 5.4 按钮

1. `.primary-button`：墨蓝主按钮。
2. `.teal-button`：青绿主按钮。
3. `.secondary-button`：白底边框按钮。
4. `.ghost-button`：轻量文本按钮。

按钮高度、圆角、字号统一，不在各页面随意定义。

### 5.5 标签和状态

1. `.pill`：普通标签。
2. `.pill-gold`：金色标签。
3. `.pill-teal`：青绿标签。
4. `.pill-red`：朱红风险标签。
5. `.notice`：底部说明。
6. `.empty`：空状态。
7. `.message`：操作反馈。

## 6. 页面改造方向

### 6.1 首页

首页要更接近 Web 端：

1. 保留居中的品牌、标题和副标题。
2. 增加一个主行动按钮“开始生成参考”。
3. 登录状态条改为设计系统卡片。
4. 模块入口使用左侧色条卡片。
5. 四个模块使用不同点缀色：
   - 照见：青绿。
   - 合缘：朱红。
   - 问时：金色。
   - 安居：青绿。
6. 卡片内容保持标题、标签、描述、行动文字。

首页不增加营销式大图，不做过度装饰。

### 6.2 表单页

四个表单页需要统一：

1. 顶部 hero。
2. 主要信息卡片。
3. 报告版本卡片。
4. 底部主按钮。
5. 隐私和风险说明。

表单项要保持足够点击高度，适合手机操作。

### 6.3 报告页

报告页要向 Web 端报告体验靠拢：

1. 顶部报告信息卡片。
2. 免费版升级提示使用金色弱强调卡片。
3. 核心摘要卡片带轻微视觉强调。
4. 报告段落卡片使用左侧青绿色细条。
5. 行动建议使用编号圆点。
6. 溯源区分命中规则、知识来源、图谱路径。
7. 免责声明保持可见。

报告页优先保障可阅读性，不堆装饰。

### 6.4 商城和订单

商城和订单页需要更像 Web 端运营面板：

1. 权益状态使用三列指标卡。
2. 商品卡突出商品名、SKU、价格和权益/库存信息。
3. 人工支付说明保持清晰。
4. 收货地址和订单入口使用统一按钮。
5. 订单状态、退款状态、发货状态使用统一 pill。

### 6.5 登录页

登录页需要统一两种方式：

1. 微信登录放在首位。
2. 手机验证码登录放在次位，并明确是模拟验证码。
3. 登录成功提示使用统一 message。
4. 不展示敏感实现细节。

### 6.6 罗盘页

罗盘页保留拟物表达，但视觉需要和整体系统统一：

1. 罗盘外圈继续使用金色、纸白、墨蓝。
2. 指针使用朱红。
3. 读数区使用卡片化结构。
4. 记录结果使用青绿弱强调卡片。
5. 操作按钮使用统一按钮类。

### 6.7 合规页

合规页需要提高阅读感：

1. 用户协议、隐私政策、报告边界按卡片分组。
2. 章节标题使用墨蓝。
3. 风险边界使用朱红或金色弱提示。
4. 正文行高保持舒适。

## 7. 实施原则

1. 优先修改 WXSS 和 WXML 展示结构。
2. 不改接口请求路径。
3. 不改页面路由。
4. 不改用户输入字段名称。
5. 不改报告、商城、订单、登录的数据结构。
6. 不引入三方 UI 库。
7. 不引入图片素材。
8. 不把 H5 代码转换到小程序。

## 8. 验收标准

完成后必须通过：

1. `npm run test:miniprogram`。
2. 微信开发者工具 CLI `preview --project D:\Projects\destiny\miniprogram`。
3. 检查小程序仍使用 AppID `wxc4ed7c07ce86326c`。
4. 检查首页、报告页、商城页、登录页、罗盘页无明显文字溢出。
5. 检查主要按钮高度稳定、文字不拥挤。
6. 检查报告页溯源信息仍能展示。
7. 检查罗盘仍调用微信原生罗盘能力。

## 9. 完成定义

小程序设计系统改造完成的定义是：

1. 小程序所有主要页面使用统一设计系统。
2. 首页、表单、报告、商城、登录、罗盘、订单、地址、合规页面视觉风格一致。
3. 与 Web 端在色彩、卡片、按钮、标签、报告阅读体验上形成同一产品气质。
4. 原生小程序边界不变。
5. 业务功能不回退。
6. 验证命令通过。
