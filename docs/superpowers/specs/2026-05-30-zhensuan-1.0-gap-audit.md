# 甄算 1.0 完整版差距审计

日期：2026-05-30

依据：[甄算 1.0 完整版范围说明书](2026-05-30-zhensuan-1.0-full-scope-design.md)

## 审计结论

当前系统已经基本覆盖 1.0 A+B 范围：原生小程序、H5、后台、Node API、PostgreSQL、Neo4j 图计算接口、图谱可视化后台、报告分层、报告溯源、人工支付闭环、会员积分权益、商城、订单、退款和发货流程均已有代码和测试证据。

1.0 仍未完成的部分主要集中在最终交付闭环：服务器真实环境验证、原生小程序 1.0 上传、上传结果记录和邮件通知。产品范围内的主要能力状态如下：

- 客户身份治理：微信真实登录、手机号模拟登录和扫码登录已经具备基础链路；已登录客户可绑定新的微信身份或手机号身份；后台可以查看、主动绑定、解绑客户身份并写入审计日志，后台已有审计日志查询页；后台已支持把冲突客户合并到目标客户并迁移报告、订单、会员、权益、积分、地址、退款等业务记录。
- 知识库发布工作流：知识、规则、模板已经具备草稿、发布、停用、版本记录、发布审计和后台版本历史查看；后续仍可继续补版本差异对比和回滚体验。
- 图计算：已具备 Neo4j 健康检查、概念路径、知识路径、规则路径、模板路径、报告路径查询和报告生成溯源写入；后续重点是服务器 Neo4j 实例最终验证和继续丰富本体数据。
- 图谱可视化：已具备后台节点图、搜索、节点类型过滤、关系过滤、展开、详情面板和从知识 / 规则 / 模板 / 报告页面跳转到图谱上下文；后续重点是服务器浏览器验收和视觉细节精修。
- 报告分层：已具备免费版 / 付费完整版 `report_tier`、完整版权益校验和扣减、H5 与小程序端入口；后续重点是运营套餐和付费转化文案精修。
- 报告溯源：已结构化保存规则命中、知识来源、图谱节点、图谱边、模板快照和安全审查快照，并在后台、H5 报告历史和小程序报告页形成可读摘要；后续重点是内容丰富度和可视化表达精修。

## 阶段优先级建议

### 第一优先级：客户身份治理

真实微信登录已经具备基础链路。下一步要把三种登录入口沉淀成可运营、可审计的客户身份体系：

- 后台查看客户的微信、手机号和扫码登录身份。
- 客户主动绑定身份，后台可主动绑定身份并解绑异常身份。
- 手机号、openid、unionid 冲突时的人工合并流程已具备基础能力，合并会禁用源客户并迁移主要业务记录。
- 身份绑定、解绑、合并写入审计日志；其中后台主动绑定、解绑、合并和审计查询已具备基础能力。
- 小程序登录失败兜底和重新登录体验继续打磨。

### 第二优先级：发布工作流

知识库专业版必须避免草稿内容污染线上报告。当前基础闭环已经具备，后续增强集中在运营效率：

- 版本差异对比。
- 指定版本回滚。
- 更细的发布审核说明。
- 批量发布前检查。

### 第三优先级：图计算与报告溯源

图计算是 1.0 的专业壁垒。必须补：

当前基础闭环已经具备，后续重点从“补能力”转为“线上验证和内容丰富”：

- 在服务器确认 Neo4j 健康检查、图查询和报告生成溯源链路。
- 继续丰富概念、知识、规则、模板和报告之间的关系数据。
- 精修报告溯源摘要，让客户和后台编辑都能理解“报告为什么这么说”。
- 逐步补跨体系路径权重和路径解释文案。

### 第四优先级：图谱可视化

可视化是后台可维护性的核心。必须补：

当前基础交互已经具备，后续重点是可用性验收：

- 在服务器后台用浏览器实际检查图谱加载、搜索、过滤、展开和详情。
- 检查从知识、规则、模板、报告页面进入图谱上下文的跳转。
- 继续优化复杂节点较多时的布局、滚动和详情阅读体验。

### 第五优先级：报告分层和商业补强

在登录、发布和溯源之后，再做产品层收费体验：

报告分层、权益扣减和基础商业闭环已经具备。后续重点是运营体验精修：

- 继续打磨免费版到完整版的升级表达。
- 继续精修会员套餐、次数包、数字资料和实物商品的运营配置。
- 继续补退款运营统计、售后备注和异常补偿流程。
- 未支付订单关闭、待支付支付单取消、发货状态校验、物流信息校验、发货审计、退款审核审计和后台反馈已经具备基础能力。

## 不纳入 1.0 的边界

本审计确认以下项目仍不纳入 1.0：

- 真实微信支付 API。
- 真实微信退款 API。
- 真实腾讯云短信 API。
- 真实快递查询 API。
- 分销代理体系。
- 专家入驻和人工咨询平台。
- 多商户商城。
- 一次性写满 518400 种命盘解释。
- 一次性完整上线六爻和奇门全部体系。
- 实时联网搜索生成报告。
