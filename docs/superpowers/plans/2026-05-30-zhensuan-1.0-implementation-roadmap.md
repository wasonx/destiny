# 甄算 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the 甄算 1.0 A+B scope as a formal operating system with real WeChat login, simulated phone login, no real WeChat Pay or Tencent SMS, graph computation, and graph visualization.

**Architecture:** Keep Node/Express as the single API, PostgreSQL as the business source of truth, Neo4j as the relationship and provenance graph, React/Vite for H5/admin, and native WeChat mini-program code for the mini-program. Each phase must leave the system deployable and must not introduce real payment or real SMS providers.

**Tech Stack:** Node.js, Express, PostgreSQL, Neo4j, React, Vite, TypeScript, native WeChat mini-program WXML/WXSS/JS, Node test runner, Python unittest scaffold checks.

## Phase Order

### Phase 0: Real WeChat Login

Detailed plan:

- `docs/superpowers/plans/2026-05-30-zhensuan-real-wechat-login.md`

Purpose:

- Replace backend `mock-wechat-${code}` identity creation with a real WeChat `code2Session` provider.
- Keep phone login simulated.
- Keep QR login.
- Preserve the existing customer token/session model.

Primary files:

- `server/config.mjs`
- `.env.example`
- `server/auth/wechat-session-provider.mjs`
- `server/routes/customer-auth-routes.mjs`
- `server/app.mjs`

- `server/tests/customer-auth-wechat.test.mjs`
- `tests/test_phase6_online_integration_scaffold.py`

Verification commands:

```bash
npm run test:server
npm run test:py
npm run test:miniprogram
npm run lint
```

Exit criteria:

- Mini-program sends a real `wx.login` code without a `mock-code` fallback.
- Backend exchanges code for `openid` and optional `unionid`.
- Existing identities are reused by `unionid` or `openid`.
- Customer token is returned through the existing session mechanism.
- No real WeChat Pay or Tencent SMS code is introduced.

Create a separate detailed plan before implementation:

- `docs/superpowers/plans/2026-05-30-zhensuan-graph-computation-provenance.md`

- Knowledge path query links `Knowledge -> Concept -> Source`.
- Rule path query links `Rule -> Knowledge -> Concept -> RiskBoundary`.
- Template path query links `Template -> Rule -> RiskBoundary`.
- Report path query links `Report -> Rule -> Knowledge -> Concept -> Template`.

Verification commands:

```bash
npm run test:server
npm run test:py
npm run lint
```

Exit criteria:

- `/destiny-api/admin/graph/...` endpoints return normalized graph payloads.
- Report history can retrieve provenance for a generated report.
- If Neo4j is unavailable, report generation returns a controlled degraded result or an explicit service error according to the detailed plan.

## Cross-Phase Guardrails

- Do not add real WeChat Pay API V3 signing or merchant certificate logic in 1.0.
- Do not add real Tencent Cloud SMS sending logic in 1.0.
- Do not convert H5 code into mini-program code.
- Do not let draft knowledge, draft rules, or draft templates affect online report generation.
- Do not let the large model generate theoretical basis without local knowledge and graph context.
- Do not commit secrets or server credentials.
- Leave unrelated working tree changes untouched. Current known unrelated change: `miniprogram/project.config.json` changed `libVersion` from `latest` to `3.15.2`.
